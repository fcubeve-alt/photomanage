## 三件需要解释的事

**为什么"账号体系"的答案是不做。**
这个产品不联网、不存任何东西在服务器上。加一个账号，意味着为了卖一样根本不需要邮箱的东西
而去收集一个邮箱地址——它会把"我们不持有你的任何数据"这句话变成假的。购买绑定在 Apple ID
上，换设备用 `AppStore.sync()` 恢复，不需要账号。**这是一个决定，不是一项缺失。**

**为什么崩溃上报不接 Crashlytics / Sentry。**
它们的工作方式就是把报告发到别人的服务器。竞品拆解（`20_TIER0/evidence/COMPETITOR_PRICING_MATRIX.md`）
记录了这个品类里的标准做法：用户付了 $7.99/周之后，元数据仍然经由 6 个以上追踪 SDK 外传，
而隐私标签写着"未关联到你"。装一个那样的 SDK，再写一份"不收集任何数据"的隐私政策，
就是同一个谎言换了个名字。所以崩溃记录写在本机，下次启动时**把全文给用户看**，
由用户自己决定要不要用自己的邮件发出来。**代价是我们会漏掉绝大多数崩溃**，
这是为了那句话是真的所付的价。

**为什么支付代码可以在没有账号的情况下写完。**
`PVM.storekit` 是一个本地 StoreKit 配置文件。购买、恢复、取消、退款的全部代码路径可以在
模拟器里跑通，不需要开发者账号，也不需要 App Store Connect 记录。
**但要说清楚它证明了什么**：它验证的是我们的代码，不是 Apple 的服务器。
**目前没有任何一次购买跑在真实商品上。**

## 仍然只有 Owner 能做的四件事

1. **Apple Developer Program（$99/年）** —— 硬门槛。Owner 已接下。
2. **一个支持邮箱**（建议别用个人主邮箱，见 `SUPPORT.md` 第 3 节）。
3. **两个公开 URL**（支持页 + 隐私政策页）—— GitHub Pages 即可，零成本。
4. **定价裁决** —— `PRICING_PROPOSAL.md`，三选一。

## 仍然是"没有数据"的部分

本目录**不改变**上一次判断里那张表：A3 生存性、删除→恢复、真实照片准确率、A1 规模，
四项全部是零数据，而这四项要装到真机上才有答案。

**这十项做完不等于可以上线。** 它做完的是：当真机验证通过、账号到位的那一刻，
不再有任何非工程的东西挡在中间。
