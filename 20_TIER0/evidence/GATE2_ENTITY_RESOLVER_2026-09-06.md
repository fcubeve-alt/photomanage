# Gate 2 — Category-Specific Entity Resolver

Generated by `eval/evaluate_entities.py`. **The corpus is hand-built.** The 10k
labelled library carries category labels and no same-entity labels, so there was
nothing to measure against; `eval/entity_pairs.py` constructs the pairs, hard
negatives included, and says why each is labelled as it is. These are cases a
person wrote down, not a sample of a real library — a resolver tuned until this
goes green is tuned to this file. Read it as evidence about the hard negatives,
not as a population estimate.

## The number Tier 1-B passes or fails on

**Document False Merge: 0 of 6 different-document pairs (0.0%).**

Wrongly merging two people's ID cards costs far more than missing a match,
so the resolver is built to be asymmetric: a document merges on a shared
identifier or a shared holder, never on looking the same. The price is paid
in the review column, which is the trade Tier 1-B asks for.

## What this does not measure

* Real libraries. Hand-built pairs cannot report a rate that transfers.
* Two views of one object. `obj-same-chair-other-angle` is labelled SAME and is
  expected to come back REVIEW: without a visual embedding nothing in this build
  joins two angles of one chair. Tier 1-B names embeddings for exactly this, and
  the pair is kept in the set so the gap shows up in the numbers rather than in
  a footnote.
* Whether the resolver beats a person doing it by eye — Tier 1-B's second PASS
  criterion needs users, which is T0-B.
